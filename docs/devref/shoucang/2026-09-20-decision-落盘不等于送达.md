# [项目事实] decision · 落盘≠送达：群聊发言必须唤醒主持人

- 卡类型：decision
- 溯源：src/rpc.ts 的 roundtable/say · v0.2.49
- 源会话：session-4110fe62-2107-487a-a7b6-6e78eb7ae1e7
- 工作区：D:\lk\FF\dsh-plugin-roundtable

用户在群聊窗口说的话落成 `nodeKey=captain` + `source='user'` 的发言。**只 appendUtterance 落盘是不够的**：会议空闲/结束时没有任何人或事会回应它，而同一个输入条在空状态那一屏会 steer 主持人开局——两处行为不一致。定案：落盘后 steer 主持人，并如实回 `delivered`（无活 agent 时 false，前端显示明确提示，**不假装已送达**）。三条实现约束：①唤醒放在会议锁**之外**（steer 会推进入主持人回合，不该占锁；与 roundtable_send_message 同理）②转交必须**加壳**（`Message from the user (meeting group chat): …`），裸传原文会让主持人分不清是用户本人在说话还是插件注入的文本 ③`source` 字段的**唯一目的**是让主持人区分"用户亲口说的"与"我自己说的"，故必须真的进入主持人可读面——修前它只到得了浏览器（wire.ts），status/汇聚网关/导出四处全不带，等于声明了不成立；现由 `src/utterance-source.ts` 的 `userSourceMark()` 单点提供标记（四处各写字面量必漂移）。
