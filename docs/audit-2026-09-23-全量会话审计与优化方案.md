## 2. 根因（收敛为 3 条）

### R1 · 一次重构把 `connect` 静默架空了 —— 且**没有任何信号**

**实证链（三步全部可复现）**：

1. **语义层**：`src/charter.ts:33` 原文 —— "单线制下刻意**不拼** roster/edges —— 名册段本身就是'还有别人'的泄露面"。而 **27/28 场是 orchestrated（= 单线制）** ⇒ 专家**读到的总纲里根本没有边**。
2. **行为层**：`send_message` 的 `execute` 只校验三件事（`src/tools.ts:1114-1161`）：`work_item` 在本轮 plan 内（`:1124`）、模式策略 `recipientPolicy`（`:1138`）、收件人在节点名单（`:1158`）。**全程不读 `meeting.edges`**。
3. **统计层**：边使用 **113 → 13**，拐点与提交 `8088c2f`（`v0.2.37–v0.2.40：圆桌三模式语义`，2026-09-19 16:41 +0800）**同步**。

⇒ **定性**：`connect` **不是天生无用的装饰**，而是**被 2026-09-19 的三模式重构架空了**——重构把可见性判据集中到 `recipientPolicy`（按 mode），**边从"决定谁能发给谁"退化成"只给 UI 看的图"**，但：

- **工具描述没改**（`src/index.ts:110` 仍在教："Wire the topology … `forward` = pipeline hand-off, `bidirectional` = debate channel"），
- **`status` 输出没标**（`src/tools.ts:2123` 仍平铺列出 edges），
- **没有任何测试或判据覆盖"边是否还有用"**。

⇒ 主持人在被教着画一张**在这个模式下不产生任何效果**的图。**这是"拆东墙补西墙"的教科书形态**：新语义拆掉了边的职责，却把"画边"这个动作留在提示词里当装饰。

> **附带发现**：`egalitarian`（唯一真正消费 edges 的模式）**0 生产使用** ⇒ **边的唯一合法用途落在了一个没人用的模式上**。这才是"0 使用"与"113→13"两件事的共同解释。

### R2 · 「建议」不是「门」—— R1 设置卡有 23% 绕过率

**实证**：`roundtable_create` 无任何前置检查；"先调 `plan_meeting`"只写在 description 里（`src/tools.ts:380`，措辞为 `Preferred flow` / `Call it for EVERY meeting`）。

**实测绕过 8 次 / 35 次 create（23%）**：

```
情境维度体系重构会审 / 情境维度体系重构会审v2 / 情境轴去留裁决  (session-63555570-649)
domain-routing-v2                                            (session-87161bb5-4d7)
effort-e2e-probe                                             (session-b7ba3eec-62d)
r-d-live-verify / r-dui-verify / r-d-egalitarian-verify       (session-c18372a4-f07)
```

⇒ 用户**在不知情的情况下**会议已被创建（无设置卡 = 没有确认席位/预算/模式的机会）。这与本仓自称的 **R1 纪律**（"NEVER create a meeting straight away"）**直接冲突**。

⚠ **须诚实区分**：其中 3 场是插件作者自己的**验证会议**（`r-d-live-verify` 等），绕过很可能是**有意为之**（测 `create` 本身）。其余 5 场（含 `domain-routing-v2` 这样有 8 条边、21 行的真实会议）则**不是**。⇒ 判据应允许**显式**绕过（见册二），而不是一刀切禁止。

### R3 · 分歧处置无对账 —— 22 条 decisions / 28 场

**实证**：`decisions` 仅 4 场有值（`role-presets-self-review` 2 · `ui-优化会审` 4 · `project-nav-anticipate-duplication` 2 · `preset-effort-row` 3 …），**24 场为零**。

而那次样本会议**明确产出 5 条待拍板项**（O1/O2/O3/O4/O5 + ★最优先）——**全部写在方案正文里，未走 `request_decision`**。

⇒ 会议**产出了分歧，但没有"分歧被怎么处理"的收口判据**。主持人靠自觉把意见折进方案 ⇒ **反对意见静默丢弃 = 用户最担心的"拆东墙补西墙"的温床**。

### 册零 · 消除 `connect` 的**双真相**（**P0 · 直击 R1**）

**判因**：三模式重构（`8088c2f`）把边的职责拆掉，但**提示词仍在教主持人画边**，`status` 仍在平铺展示边，**没有任何判据覆盖"边是否还有用"**。

⇒ 这是本仓自有的「**两种真相**」缺陷形态：**实现按 A（边不参与可见性）、文案按 B（边是协作拓扑）**。实测代价：18 场会议画了 122 条边，而专家**一个字都读不到**。

**做法（分模式，因为两种模式的病不同）**：

| 模式 | 现状 | 做法 |
|---|---|---|
| **orchestrated / redteam**（27/28 场） | 边既不进总纲、也不参与送达 ⇒ **零作用** | ① `roundtable_connect` 的工具描述**按当前模式**给出差异文案：单线制下明确写「边在本模式下**不参与送达、专家不可见**，仅用于主持人自述的协作图；如需表达先后关系，请用 `next_round` 的 `depends_on`」② 建会时 `status` 的 edges 段加注 `（装饰 · 不影响送达）` |
| **egalitarian**（0 场） | 边是**唯一**真正被消费的地方（总纲会拼 roster+edges，`charter.ts:41-55`） | **不动**。它是边语义的正当归属地 |

**为什么不做"给单线制的边加消费面"**：单线制的**定义**就是"专家互不披露"（`charter.ts:37`）⇒ 让边影响送达会**直接违反三模式语义**（用户 2026-09-19 定稿）。**正解是把残留的期待去掉，而不是把边硬塞回可见性**。

> **与用户主张的一致性**：用户主张"**主张信息皆可重构与统一压缩**、**反对冗余堆叠**"。本册不删 `connect`（egalitarian 需要它），而是**让文案与实现同源**——这正是"统一压缩"而非"再加一层"。

**验收**

| # | 判据 | 检查方式 | 阈值 | 先红证据 |
|---|---|---|---|---|
| C-1 | 边不参与送达（**现状确认，锁住不回归**） | 夹具：单线制 + **零边** ⇒ `send_message` 仍 `delivered=wake` | 必须成功 | 现状即如此；夹具缺失 ⇒ **本判据当前为"未验证"** |
| C-2 | 工具描述随模式差异化 | 断言 `connect` 的 description 在单线制下含"不参与送达" | 精确包含 | **改前不含** ⇒ 先红可证 |
| C-3 | `status` 边段带注 | 断言单线制下 edges 段含"不影响送达" | 精确包含 | 改前不含 ⇒ 先红 |
| C-4 | egalitarian 的边**仍进总纲** | 夹具：egalitarian 会议 ⇒ `buildCharter` 输出含 edges | 精确包含 | **现有测试可能有覆盖，须先查** |
| C-5 | 零回归 | `test/*.test.mjs` 中 mode/persona/charter 相关全绿 | 全绿 | —— |
| C-6 | 不新增模块 | `check-module-growth` 模块数不变 | 前后同值 | —— |
| C-7 | **新增**：边的消费面清单可查 | 文档/注释列出 edges 的**全部**消费方（charter/egalitarian · snapshot/UI · rpc 增删） | 三处齐全 | 改前**无此清单** ⇒ 先红 |

### 册一 · R1 设置卡：给 `create` 一个**可显式绕过**的门（**P0 · 直击 R2**）

**判因**：23% 绕过率；其中多数非测试用途。

**做法**（**不搞一刀切**，兼顾验证场景）：

`roundtable_create` 增参数 `skip_plan_card?: boolean`：

- **未传** 且本会话**没有**与该 `name` 配对的 `plan_meeting` 批准记录 ⇒ 抛出错误，提示"先调 `roundtable_plan_meeting`；若确为验证/脚本用途，显式传 `skip_plan_card: true`"。
- **传 `true`** ⇒ 放行，**并在 `meeting.json` 记 `planCardSkipped: true`**（留痕，可事后统计）。

**为什么是"显式绕过"而不是"硬门"**：插件作者需要写验证会议（实测 3 场），硬门会挡住正当用法；而**显式**绕过把"我知道我在跳过用户确认"变成一个**必须说出口的事实**——正是本仓自有的「留痕字段必须有消费面」纪律。

**配套消费面**：`roundtable_status` 增 `plan_card_skipped` 字段，使"这场会议没让用户确认过"**在事后可查**。

**验收**

| # | 判据 | 检查方式 | 阈值 | 先红证据 |
|---|---|---|---|---|
| P-1 | 未确认即建会 ⇒ 报错 | 夹具：直接 `create` 不带 `skip_plan_card` | 必须 throw | **现状不 throw** ⇒ 先红可证 |
| P-2 | 显式绕过 ⇒ 成功 + 留痕 | 夹具：带 `skip_plan_card:true` | `planCardSkipped===true` | 改前无此字段 ⇒ 先红 |
| P-3 | 正常流程零回归 | 既有 `plan` 相关夹具全绿 | 全绿 | —— |
| P-4 | 可事后统计 | `status` 含 `plan_card_skipped` | 布尔精确 | 改前无 ⇒ 先红 |
| P-5 | 报错文案可操作 | 断言含 `skip_plan_card: true` 字样 | 精确包含 | —— |

### 册二 · 分歧处置对账：新增 `dispute` 席 + 收口判据（**P1 · 直击 R3**）

**判因**：24/28 场零 `decisions`；反对意见的最终去向**无任何记录**。

**做法（两半，缺一不可）**：

**① 新增 1 席预设 `dispute`（争议归位）**


**缺陷式**（修复前 `src/tools.ts` 的 `renderStatus`）：

```js
const route = String(candidate.provider ?? '') === '' || String(candidate.model ?? '')
  ? '（继承主持人路由）'
```

`||` **右侧漏了 `=== ''`** ⇒ 它返回的是 model 字符串本身（truthy）⇒ **整个条件恒真**。

**修法**：改为双向非空判定 `provider !== '' && model !== ''`，与 `list_presets` 的口径取反等价。

**真机证据**：修复前 `（继承主持人路由）`×28 → 修复后 `dshapi/deepseek-v4.1-flash`×28。

### 12.1 关键设计决定：两条要求收敛到**同一个结构**

没有为两条要求各造一套机制。**边界声明**（`goal` / `done` / `notDoing`）同时承载两者：

| 要求 | 由哪一项承载 |
|---|---|
| 边界/目标不清先澄清 | `goal` + `done` 填不出 ⇒ 必须先问用户 |
| 防拆东墙补西墙 | **`notDoing` = 不许拆的那面墙** ⇒ 每次改动对照它自检 |

⇒ 与用户自建项目治理的 `nav_set(doing/next/notDoing/exit)` **同构**——沿用用户既有方法论，不另造。

### 12.2 ① 澄清前置（边界不清不得开工）

**判因**（实测 · 会话 `690079f3`）：主持人把用户含糊的「容量门」**自行转述**成一个具体定义后直接开会，
**会议结束后**才澄清，付出一整轮作废的代价；主持人自认「全仓查无你的原话，只有转述」。

**落点**：`usage rule 1` 加前置判据——三项中任一项**无法用用户原话回答**即属转述，须先问一个短问题并等回答；
并把实测代价（会话 id + 原话）写进规则**留档**（使后来人删掉它需先推翻证据）。

**四段贯通**（缺一段即为断链）：

```
① 类型       MeetingBoundary { goal, done, notDoing } + Meeting.boundary   （types.ts）
② 卡片       「边界确认」块；未声明时**显式警示**（不静默省略）              （plan.ts）
③ 会议记录   create 落盘 boundary；status 每轮回吐（未声明也显式报）         （tools.ts）
④ 总纲/导出  进每个专家的 persona + 进导出物（事后可复盘是否越界）            （charter.ts / tools.ts）
```

### 12.3 ② 防拆东墙（全流程，不只是一步）

`usage rule 17` 四条操作要求（写入协议，非劝告）：
(a) 每条计划项填 `regression_risk`（可能碰坏什么 + 怎么确认没碰坏）；
(b) 不接受专家「顺带修好了 X」当红利，须追问碰了哪个既有行为、证据在哪；
(c) 确需越界**先说再做**并取得用户明示同意，**禁止改边界来迁就现成方案**；
(d) 收口时**如实报告**发生过的越界及其证据。

**四段贯通**：类型 `regressionRisk` → 归一（snake_case + **空串折叠成缺省**）→ 信号 `risk_items_missing` → 渲染 `regression self-check: N/M`。

### 12.4 关键取舍：`regression_risk` **只呈现不判定**

曾拟「按动词关键词判哪条是改动型工作项，改动型必填」。**主动放弃**，理由留档：

- 分类启发式会造出假红假绿（"分析接口"含"分析"却可能要改代码；"实现 X"明明是改动却可能被动词表漏掉）；
- 强制填写会逼出"无风险"这类凑数文字，反而使真风险淹没——正是「为不存在的需求付出的复杂度」。

⇒ 机器**判不了**"是否真风险"，故只做**计数与点名**，让缺口**可见**，由人/主持人决定是否追问。
这与本插件既有的「留痕字段必须有消费面」是同一取向：**不替人下结论，但绝不让缺口静默消失**。

### 12.5 ③ 构建产物守卫（本轮实测事故后补）

**实测事故**：`npx tsdown` 遇语法错误时**先 `Cleaning N files`（删光 lib/ 产物）再失败**。
后果：宿主 loader entry 指向 `lib/index.js`（junction），产物没了 = 插件加载不了，
而 **`npm test` 仍 337 全绿**（测试直接读 `src/*.ts`，不读 `lib/`）；
`tsc --noEmit` 报的又是**预存**的宿主依赖漂移错误 ⇒ 极易把"构建失败"归因到那批预存错误上而**忽略 lib/ 已被清空**。

⇒ 新增 `test/build-artifact-guards.test.mjs`（3 条）：产物存在且非空 / 不比 src 旧 / 含本轮能力标记。

⚠ **容差 5 秒是刻意的**：`git clone` 是逐文件写盘的，写 `lib/` 与写 `src/` 的先后不由仓库内容决定
⇒ 严格比较会在全新克隆上**随机假红**，而一条会随机假红的守卫**比没有守卫更坏**（它训练人忽略它）。

### 13.1 关键修正：上一批的缺口

第二批只做了 `regression_risk`——那是**产出者自检**，而**自检本身就是自产自审**。
用户这条要求补上了**独立的第二双眼睛**。三者的分工（**不可混**）：

| 机制 | 谁来做 | 强度 | 本批状态 |
|---|---|---|---|
| `regression_risk` | 产出者**自检**（我可能碰坏什么） | 弱 | 第二批已有 |
| **`kind:'review'` 独立审查项** | **另一席**（拆东墙 vs 根因解决） | **强** | **本批新增（硬门）** |
| `close` 分歧处置提示 | 主持人收口对账 | 中 | 第一批已有 |

### 13.2 自产自审硬门（三形态全拒 · 运行时实测）

判据在 `dispatch.validateRoundPlan`，**确定性、无启发式**：

| # | 形态 | 判据 | 实测 |
|---|---|---|---|
| ① | **改动无审查** | `change` 项无 `review` 项 `dependsOn` 它 | **REJECT** ✓ |
| ② | **同席自审** | 审查席 owner === 该 change 的 owner | **REJECT** ✓ |
| ③ | **交叉自审** | 审查席 owner 也是本轮任一 change 的 owner | **REJECT** ✓ |

**豁免**：在场席 <2 时跳过（结构上无法分席——不是纵容，是做不到）。
**不拦未声明 `kind`**：机器判不了未声明项有没有改动面（按动词猜已明确放弃）；由 `round_signals.kind_unspecified` 报出使缺口**可见**。

**为什么必须是硬门**：产出者审自己的产出，**结构上**不可能发现"我这次拆了哪面墙"——它只知道自己想改什么。
这与用户自建项目治理的「记忆准入与审查**同源**」是同一判据：**入库门与用户审查门同一判据即自净**。

### 13.3 独立审查覆盖面（硬门管不到的半覆盖）

硬门只保证"每个 change **至少有一个**审查项存在"。**半覆盖**（3 个改动只覆盖 1 个）由 `round_signals` 报出：

```
independent review: 1/1 change item(s) covered by a review owned by a DIFFERENT seat
  ⚠ change without independent review: <ids> — 自产自审发现不了自己拆的墙
  · kind unspecified: <ids> — if any of these produces a change, declare it kind:"change"
```

分母 **always render**（沿用 `planned_owners` 的教训：只在有缺口时打印，读者就看不到比较基准）。

### 13.4 锚定用户原话（绝对避免偏离）

`meeting.userDirective` = 用户**未加工的原始指令**，**四段贯通**：

```
① 卡片     原样回显「你的原话（逐字）」（在主持人转述**之前**，便于一眼对照）  （plan.ts）
② 会议记录 create 落盘 userDirective                                          （tools.ts）
③ status   每轮渲染 USER DIRECTIVE (verbatim — every round must still serve THIS)
④ 总纲     一之一、用户原话（**最高优先级**；与目标冲突时以本条为准）            （charter.ts）
⑤ 导出     留档，否则事后只能看到转述、永远查不出偏离                          （tools.ts）
```

**为什么必须存原话**：实测（会话 `690079f3`）主持人把含糊的「容量门」转述成自己的定义后开工，
**会议结束后**才发现要解的不是那个问题，一整轮作废；主持人自认「**全仓查无你的原话，只有转述**」。
⇒ **转述一旦覆盖原话，偏离就无法被发现**。

### 13.5 主持人职责写成闭环（rule 18 / rule 19）

- **rule 18 禁止自产自审**：按任务类型选审查席（`arch` 审架构 / `verify`·`repro` 审"这claim是否属实" /
  `security`·`data`·`perf` 审对应面）；审查回来由主持人判断，**发现是补丁不得静默接受**——
  重新派单（新改动 + 新独立审查）或把分歧交用户。
- **rule 19 锚定用户指令**：主持人闭环 = **澄清意图 → 编排计划 → 下发 → 判断返回 → 再次下发**，反复至达成。
  并明确**什么不算进展**：有意思但没被要求的工作 / 你替用户换掉的问题 / "顺便"扩大范围。
- **rule 17(e)**：派单时把防拆东墙要求**写进任务正文本身**（不只留在协议里）。
