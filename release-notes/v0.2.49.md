## 1. 本轮修的是一个真缺陷：中文输入按 Enter 会发出半截话

**位置**：`src/client/ChatComposer.tsx`（群聊窗口与空状态窗口共用的那一个输入条）

原实现：

```tsx
if (event.key !== 'Enter' || event.shiftKey) return
event.preventDefault()
submit()
```

没有 IME 组合态守卫。中文/日文输入法里「按 Enter 选定候选词」与「按 Enter 发送」**是同一个键**，组合期间 `key` 同样是 `'Enter'` —— 于是用户选词时就把半截拼音或未完成的正文发了出去。而两个占位文案恰恰在**宣传**「Enter 发送」，等于诱导踩坑。

对照证据：宿主自己的编辑器是拦的 —— `dsh-client-ui-conversation/lib/client.js` 里 `if (e.isComposing()) return;`。本插件全仓 `isComposing` **零命中**。

**修法**：把按键决策提成可直测的纯函数 `shouldSendOnKey(key, shiftKey, isComposing)`，并说明为何必须取 `nativeEvent`（React 合成事件上没有 `isComposing`）。

**为什么提成纯函数**：这条规则**在渲染面上不可观测** —— SSR 渲不出按键行为，原有 6 条渲染断言全绿也照样能把这行守卫删掉。提出来才能真断言（见 §4 变异 24）。

## 2. 两处"注释声明了、但实际不成立"的地方

### 2.1 「先置模式再 steer」顺序（`src/rpc.ts` 的 `roundtable/steer`）

注释把这条列为"三条刻意的选择"之一（模式段是 system prompt 的一部分，顺序反了会出现"议题已转交但主持人不知道按圆桌处理"的窗口）。而守卫只断言两个子串**都存在** —— 把两句对调后 `includes` 断言**照样全绿**。

**实测**：对调后 `# fail 0 / # pass 304`，无守卫转红。
**修法**：加 `indexOf` 顺序断言，并配变异 19 证明它不是摆设。

### 2.2 `source: 'user'` 到不了主持人（`src/rpc.ts` 声明 vs 四处读取面）

`roundtable/say` 的注释写明这个字段的目的：让主持人下一轮**区分"用户亲口说的"与"我自己说的"**，否则"把用户的话当成自己的话 —— 那是归因错误，不是风格问题"。

但逐面核对，四类面向主持人的读取面**全部不带它**：

| 读取面 | 位置 | 修前 | 修后 |
|---|---|---|---|
| `roundtable_status.recent_utterances` | `src/tools.ts` | ✗ | ✓ `from_user` |
| `roundtable_summarize` 汇聚网关 | `src/aggregator.ts` | ✗ | ✓「（用户）」 |
| `roundtable_export_meeting` | `src/tools.ts` | ✗ | ✓「（用户）」 |
| 浏览器群聊 | `src/client/wire.ts` | ✓ | ✓（不变） |

即：那条区分**只到得了浏览器**。主持人确实看得到这条消息（显示为 `captain`），但分辨不出来源。

**修法**：新增 `src/utterance-source.ts`（`isUserSourced` / `userSourceMark`），四处引用**同一个**标记函数 —— 四处各写各的字面量必然漂移。标记用「（用户）」而不是「我」：读它的人可能不是用户本人，导出物里「我」是相对视角、会误导。

## 3. 落盘 ≠ 送达：群聊发言现在会唤醒主持人

**位置**：`src/rpc.ts` 的 `roundtable/say`

修前：只 `appendUtterance` 落盘，**不 steer、不唤醒**（实测该 case 体内 `steer`/`wake`/`notify` 零命中）。

后果：会议空闲/结束时用户在群聊里说一句话，气泡出现了，但**没有任何人或事会回应它**。而且同一个输入条在空状态那一屏会 steer 主持人开局，在这里却毫无反应 —— 两处行为不一致。

**修法**：落盘后 steer 主持人，并把结果如实回给前端：

- 唤醒在会议锁**之外**（steer 会推进入主持人的回合，不该占着会议锁；与 `roundtable_send_message` 同一理由）
- 转交时**加壳**：`Message from the user (meeting group chat): …`（裸传原文会让主持人分不清是用户本人在说话、还是插件注入的文本）
- 没有活的主持人 agent 时回 `delivered: false`，前端显示明确提示 —— **不假装已送达**

## 4. 假绿自查：变异探针的判定加严了

`test/mutate.mjs` 原判定是 `# fail > 0 ⇒ PASS（守卫真的转红）`。这个判据**区分不出**：

- (a) 目标守卫抓到了这次变异；还是
- (b) 别的原因把套件弄红了（把源码改成语法错误时整个文件的测试都会红，目标守卫**根本没机会执行**）

**实测**（把变异 4 的锚点改成语法错误）：

```
旧判据 (# fail > 0)     : PASS  ← 假绿
新判据 (须命中期望文案) : FAIL  ← 正确拒绝
```

**修法**：判定改为「必须有**失败块内部**出现本变异的 `expect` 文案」。切块（`not ok` 起、到下一个 `ok`/`# ` 止）而不是全文搜 —— 测试名与位置也在输出里，全文搜会把"另一条测试碰巧提了这句词"算成命中。

`expect` 由此从一个**死字段**（修前：`Select-String "\.expect"` 零命中）变成**真判据**。

### 顺带：加严后立刻抓出三项

| 项 | 问题 |
|---|---|
| 变异 2 | 锚点因缩进变化失配（`say` 改写后多了一层） |
| 变异 7 / 10 / 11 | `expect` 写的文案与**实际响的断言消息**不一致（探针此前不校验，从未暴露） |
| 变异 21 的守卫 | **恒真**：原断言只查 `from_user:` 这个键出现过，而 `from_user: false,` 同样含它 —— 已改为断言完整取值表达式 |

## 5. 截断提示不再靠客户端猜

**位置**：`src/rpc.ts` 的 `selectTranscriptWindow` + `src/client/wire.ts` / `RoundTableView.tsx`

修前：客户端用本地常量 `TRANSCRIPT_PAGE = 200` 与返回条数比较来推断"上面还有更早的发言"，而 host 侧的夹取上限 `TRANSCRIPT_LIMIT_DEFAULT = 200` 是**另一份**常量、彼此不知道（实测：双向 import 关系为零）。

危险方向是 host 改**小**：host 限 100 时，满页 100 条 → `100 >= 200` 为 false → `truncated = false` → **用户被静默隐瞒了"更早的发言未载入"**。

**修法**：`truncated` 由 host 判定（它看得见全量）并随数据一起回；客户端删掉本地常量，只负责显示。判定因此从"猜"变成**精确**。
