# RoundTable v0.2.45

**角色预设的「模型 · 思考强度」落地**：模型/厂商/**思考强度**三项一起并进「编辑」表单——列表里点某条「编辑」，表单就**长在那一条下方**；档位词表**逐字来自宿主**（不自造枚举），并一路贯通到专家节点的真实模型请求头。

---

## 1. 一个入口，而不是两个

最初的做法是在每条预设下另起一行加一个「模型 · 思考强度」按钮。审阅后收掉：**同一件事实不该有两个可写处**。

现在只有「编辑」这一个入口，它同时管四个字段（名称 / 角色说明 / 厂商+模型 / 思考强度），并且**行内挂载**——点第 5 条的「编辑」，表单就长在第 5 条下方。原实现的表单挂在**整份列表下方**（`RoundTableSettings.tsx` L425-479），列表本身是 260px 滚动容器（`module.css` L259-265）：改第 5 条时表单在视口外，用户必须在"改第几条"和"改了哪个字段"之间来回滚动。

表单抽成独立组件 `PresetForm`（`inline` 开关决定挂条目内还是挂列表下方），行内编辑与「新建预设」共用同一张表单——抄两遍必然漂移。

档位这一项此前**完全没有**：`rolePresets` 只有 id/name/role/provider/model。

## 2. 词表唯一来源（硬约束，写进代码注释与测试）

`ctx.llm.listModels()` **不带 reasoning**；只有 `resolveModelInfo(provider, model)` 返回 `reasoning.efforts[].id/name`。照 `listModels` 读 `reasoning` 会**恒为 undefined**，UI 表现为"等级下拉只剩继承一项"——不抛错、不消失，**纯静默失败**。所以：

- `roundtable/models.list`（`src/rpc.ts`）改为对每个模型补一跳 `resolveModelInfo`，逐模型附 `reasoning:{efforts,defaultEffort?}`；
- `reasoning` **字段在场/缺席**分叉：模型不提供推理 ⇒ 字段**缺席**（空 `efforts` 数组是非法值，宿主会抛 `INVALID_MODEL_REASONING`）；
- `defaultEffort` 不恒给，且必须落在 `efforts[].id` 里（不在则丢弃，与宿主规范化同口径）。

实测（本机 7 provider / 37 模型）：端点响应 2459 B → **7291 B**，其中 **28 个模型带档位、共 111 个档位项**，`failures` 字段在场。补这一跳是纯内存计算（`+5~20ms` 量级），**不加缓存**——缓存会引入"模型目录变了却不刷新"的失效面。

## 3. 三条真实缺陷（都是"错了也看不出来"这一类）

| 缺陷 | 位置 | 后果 |
| --- | --- | --- |
| **净化层静默丢字段** | `src/rpc.ts` L126-145 `sanitizeRolePresets` 全量重建白名单 | 不扩白名单则 `prefs.set` 写回时把 `reasoningEffort` 丢掉，**接口仍返 ok、UI 仍显示"已保存"** |
| **换路由不清档位** | `RoundTableSettings.tsx` L451/L462-463；专家管理面板同形 | 只清 model 不清档位 → 留下 `deepseek-v4.1-flash @ high` 这种假值 → 到该专家**首个请求**才炸 `UNSUPPORTED_REASONING_EFFORT`，症状与"模型慢"不可分辨 |
| **失败与"不支持"同形** | `src/rpc.ts` 旧 `catch { models = [] }` | 单模型读失败会把**整个 provider** 的模型清空（"这个厂商没有模型"），且与"该模型不支持推理"完全同形（用户看到的是错误结论，不是错误提示） |

## 4. 改法（按"逐层降级、失败留痕"）

- `models.list` 的枚举抽成**可导出纯函数** `buildModelCatalog(llm, ...)`：**逐模型 try/catch**（单模型失败只降级该模型，不再波及同 provider 的其它模型），失败进**顶层** `failures[{id,name,message}]`（provider 粒度一条，形状照宿主 `buildModelCatalog`）。
  刻意**不抄**宿主的空组过滤：本插件的 provider 下拉即使在"枚举失败"时也保留条目，否则用户会看到厂商凭空消失。
- 净化层扩白名单并透传（A1：给了就逐字保留，没给**不得**凭空出现该键）。
- 换 provider / 换 model **同时清空档位**（设置页与专家管理面板两处）。
- 档位在链路上**必须走结构化字段**：`UserAction.reasoningEffort` → `roundtable_add_node` 的 `reasoning_effort`。只塞进 `text` 会让主持人只能靠解析自然语言取值，静默丢失是必然的。
- 专家管理面板的表单也加档位下拉（同一份词表），预设下拉项显示 `@effort`，一键填充变成 4/4 字段。

## 5. 交互口径

- **编辑 = 行内展开**：点该条「编辑」即在条目内展开表单，再点一次收起（同一按钮既开又关，不另设取消键）。「新建预设」仍挂列表下方（没有"是哪一条"的问题）。
- **无档位模型**：档位控件**保留但置灰** + 同屏文案「当前模型未提供推理等级。」（沿用宿主原句）。不隐藏 —— 静默消失会让用户判不出是"这个模型没有"还是"设置没生效"。
- **滚动（M6）**：表单渲染后调 `scrollIntoView({ block: 'nearest' })`（用 `useLayoutEffect`，同一 tick 里量到的是折叠高度，等于没滚）。
- **条目级回执**：改完在**被改的那一行**显示「预设已更新」，而不是页脚一句全局提示。
- **档位摘要**：预设行摘要显示 `provider/model @effort`（不显示则用户无法察觉"设了档位但被净化层丢掉"）。

## 7. 验收（可核验证据）

- `tsc` host + client **双端 0 错**；`npm run bundle:client` 双 bundle 成功。
- `node --test`：**261/261 全绿**（v0.2.44 基线 242；新增 19 例）。
- **端点实调**（`POST /plugins/dsh-plugin-roundtable/rpc` `roundtable/models.list`）：
  `providers=7 failures=true(0条) models=37 withReasoning=28 effortSum=111`，
  样例 `deepseek-official/deepseek-flash` → `efforts=[off,low,high,max] defaultEffort=high`（含 description 逐字）。
- **A5 终判（审计态，唯一不自述的证据）**：真起一场会议，一席 `presetId=req-spec`（预设带 `reasoningEffort=high`）、一席 `presetId=scenario`（不带），跑
  `node scripts/audit-reasoning-effort.mjs --state-dir .roundtable --meeting <id>`：
  ```
  effort-probe  | 设定=high     | presetId=req-spec | frames=11 failed=0 | headers=1 | 档位出现=["high"]
  inherit-probe | 继承主持人     | presetId=scenario | frames=25 failed=0 | headers=1 | 档位出现=[]
  A5 分母 = 1；违例 = 0
  ```
  ⇒ ①预设里的档位**逐字**进了该席的 `request/header.config.reasoningEffort`；②未设档位的席**没有**该键（继承语义未被误伤）。
  审计器必须按 zstd magic `28 b5 2f fd` **逐帧**扫（本仓会话日志多帧，流式解压只吐第一帧会造出"1 行、0 条 header"的**假红**）。
- **热重载**：`dev_reload_package roundtable` → 重载前后均 `[active]`（清缓存 15 模块、重建 1 fiber，client ✓）。
- **洁净度**：取证用的临时配置从备份逐字节恢复（37784 B / 731 行 / 全文 `reasoningEffort` 27 处，全在 `llm-pi-ai` 命名空间内），探针会议已删除。
