# RoundTable v0.2.43

**R-D-UI「调度面板」批次 + R-D 自审遗留清理**。v0.2.42 把调度面（计划/候选池/对账）落到了 host；本版把它**画进拓扑页**，并修掉自审与专家席当场抓到的三处真缺陷 —— 其中一处是**同一场会议两个答案**，属最该先修的那一档（会让失败不可观测）。

---

## 1. 三条先修的真缺陷（都不是"忘了写"，而是结构缺口）

| # | 缺陷 | 证据 | 修法 |
| --- | --- | --- | --- |
| ① | **同一会议两个答案**：`snapshot.ts` 调 `buildRoundSignals` 时漏传 `onStageByPreset` ⇒ `status` 说"没漏派"，快照/HUD 说 `unplannedDispatches:["arch"]` | 活路由实测：改前快照 `["arch"]` / 探针按 tools 形状调用 `[]`；专家席（arch）独立报到同一现象 | 该参数改**必填** + 新增唯一装配入口 `onStagePresetMap()`，两个调用点同源。漏传现在是**编译错误** |
| ② | **跨轮假绿**：计划 id 只要求"本轮内唯一"（跨轮复用合法），但对账扫了全部轮次 ⇒ R2 从未派发的 `a1` 被 R1 同名记录冒充成"已追踪" | 自审探针：`tracked=1 / undispatched=[]`，应为 `0 / ['a1']` | 追踪记录只认**本轮**（`utterance.round !== round` 即跳过） |
| ③ | **圆桌制报错信号**：`[越界转派]` 是单线制专属协议（圆桌制专家直接转给同伴），却在所有模式都收集 | charter 第二节 / members.ts 的 modeRule 分叉 | `buildRoundSignals` 收 `mode`，egalitarian 下显式置空（不是关掉判据：单线制仍必须收集，已用对拍断言钉住） |

**外加**：`[越界转派]` 判据从"行内含即算"收紧为**行首标记**（容忍列表符号），并排除主持人/汇聚网关发言 —— 实测中主持人在派单里写「请按协议写一行 [越界转派]」曾被当成 **2 条真实转派**。

## 2. 判据单源化（专家席 RC1/RC2）

- `onStagePresetMap()`：`onStageByPreset` 的唯一装配入口（两个调用点，禁止各写一份 reduce）。
- `isDispatchableSeat()` / `dispatchableSeatKeys()`：**可派单席**判据（未移除 **且已出生**）单源 —— 调度侧原有 4 处内联。
- `presetLinkedSeatIds()`：**预设关联席**判据（未移除 **且有 presetId**）单源 —— 与上一条**语义不同**（未出生的席仍算认领了预设），刻意不合并，并用对拍断言钉住两者差异。
- 只收调度侧这一族：名册展示/连线/去重处的 `status !== 'removed'` 语义不同，**没收**（避免顺手改掉既有语义）。

## 3. UI 批次：调度面板进拓扑页

- host 快照新增 `plan`（本轮波次 / 对账两类偏差 / 缺口 / 越界转派）与 `talentPool`（**只下发本会议的在场标记**）。
  预设清单本身是全局的、客户端已从 `prefs.get` 拿到 —— 1Hz 轮询下**不重复搬运**（实测 16 会议快照 301 KB，按会议重复 28 条清单是纯浪费）。
- 落账计划**不可解析时**（旧版本写入 / 被手工改坏）显示提示并**拒绝画空波次图**，绝不让人把"空了"读成"本轮没任务"。
- 面板抽成独立模块 `src/client/DispatchPanel.tsx`（纯展示、无 hooks/IO）。**抽出去的理由是证据强度**：内联在 1900 行视图里只能做源码字符串断言。

## 5. 验收（可核验证据）

- `tsc` host + client **双端 0 错**；`tsdown` 构建通过（host 240.5 kB / client 541.8 kB）。
- `node --test` 逐文件跑：**22 个文件 234/234 全绿**（v0.2.42 基线 227）。
- **反验收（变异测试，逐条对应）**：
  ① 面板不画波次（`plan.waves.map` → `[].map`）→ 渲染面①红；
  ② 视图不挂载面板（`<DispatchPanel` → `<div`）→ R-D-UI③ 与 panel-ids② 同时红；
  ③ `onStageByPreset` 改名（模拟漏传）→ R-D-UI① 红。
  全部随后恢复复绿。
- **渲染面证据（本批新增的证据强度）**：`dispatch-panel-render.test.mjs` 用
  TypeScript 自带 JSX 转换 + 本地 react-dom/server **真渲染生产组件**，断言真 DOM：
  两波图的"立刻并发/等上一波"、对账两类偏差、越界转派、在场标记（含"不在场不得被打标记"的反向断言）。
  ⚠ 边界已写在文件头：这是 `DispatchPanel` 的渲染验证，**不是**整个 `RoundTableView` 的挂载验证。
- **运行态实测**（真预设席位 temp 会议，验完即删）：
  - 活路由 `/plugins/dsh-plugin-roundtable/state` 返回 `plan.waves = w1[u1→verify, u2→new:arch]`、
    `talentPool.onStage = verify,arch`、且 `talentPool` **不含** `candidates`（清单不重复搬运）；
  - 缺陷①在**同一路由**上复验：`unplannedDispatches` 由 `["arch"]` 变为**空**；
  - 两次热重载后 `lib/client.js` 经字节核对含 `DispatchPanel` / `dispatchNoPlan` / `立刻并发下发`。

## 6. 未做（明确记录，避免被当成"已完成"）

- **浏览器实机截图**：GUI 根路径受宿主进程级 launch-token 鉴权保护（`dsh-client-connection` 的
  `BrowserAuth`），无凭据不可进；伪造 cookie 会绕过鉴权，**不做**。故渲染证据止于 SSR 真渲染 +
  源码接线守卫；完整浏览器挂载留待用户在有鉴权的会话里目视确认。
- 候选池面板**不从 UI 直接拉人**（只显示在场标记）：拉人仍走主持人的 `roundtable_add_node`，
  保持"UI 不直改会议状态"的既有边界（既有约束，非本批遗漏）。
