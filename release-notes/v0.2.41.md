| 旧守卫 | 它宣称 | 实测漏洞 | 回修后 |

| `test/rpc-write-freeze.test.mjs` | "RPC 直写点恒为 4 处，新增即红" | `writeCount(4) <= cases.length(16)` **恒真**；整道门只数 `await writeMeeting(`，漏掉 `setViewpointStatus`(1)、`appendUserAction`(2)、`rm(meetingDirOf…)`(1)。往模块级的 `applyViewpointStatus` 里再加一次状态写 → **门照样绿** | 改为**符号白名单精确计数**：4 个写入符号逐条断言次数 + 「符号必须真的存在」防改名静默失效 |

## 2. `usage` 跨会议不复位（三席独立命中）

`setUsage` 原先只在 `loadUsage` 成功回调里出现，换会议（`onChange → setSelectedId`）没有任何重置路径 —— 切到另一场会议后，agents 面板继续显示**上一场**的逐节点 token/耗时，且没有"旧数据"标记，数字看起来仍然权威。

修法：`useEffect(() => setUsage(null), [meeting?.id])`；断言 `F1`（复位必须挂在 `meeting.id` 的 effect 上）。

## 3. 拖线说明按模式分叉（用户拍板 A）

原三处说明（画布常驻图例、右键菜单首行、连线成功 toast）共用**同一句与模式无关**的文案，写的是单线制的"专家互不相识、一律由主持人代转"。这在 **egalitarian（多模型平等）** 会议里是反话 —— 那里专家互相可见、可直接派单。

- 新增 `edgeScopeHintEgalitarian`：图例与右键菜单按 `meeting.mode` 分叉（两处，源码断言计数 = 2）；
- 新增 `edgeConnectedSingleLine`：单线制下连线成功 toast 说明"此连线不表示专家能直接通话，只表示转达顺序"，不再用它去暗示权限变化。

## 4. `deliverable` 从"只写不读"变成可见标注

host 侧一直计算 `edge.deliverable`，但客户端 **0 次读取**、测试 0 覆盖（同批 `implicit` 倒是被消费）。现在：不可投递的边（单线制下专家↔专家）加 `.edgeUndeliverable` 降级样式（透明度，**不用虚线** —— 虚线已被骨架边占用）+ SVG `<title>` 说明。拖完弹"已连接"不再会被读成改动了通信权限。

## 5. 用量端点与文案的两处修正

- 「没有值」的两种情形**分开说**：`projections_available=false`（宿主未挂投影）vs 该席当前无活会话（新增 `usageDormant`）。原本文案一律说"宿主未挂投影"，与端点自己回的 `projections_available: true` **直接矛盾**。
- `⏱` 按钮加 `disabled={usageLoading}`：端点会**惰性折叠整条会话日志**（第一方文档），此前只把字符换成 `…`、按钮仍可连点。

## 6. 1Hz 快照 ↔ 按需端点的边界补断言

这条边界此前**只靠注释维持**：把用量塞回 1Hz 快照，性能会静默退化且没有任何断言会红。新增 `test/snapshot-boundary.test.mjs` 3 条：① `snapshot.ts` 不得出现 `sessionProjections` / `usage.ts` / `tokenUsage`；② `rpc.ts` 的 `projections.snapshot(` 调用数恒为 **1**，且必须落在 `usage.get` 的 case 内；③ `projections_available` 不得写死。变异（给快照塞一行 import）→ 转红。

## 7. 弹窗键盘可达性（第一步）

`src/client` 全目录 `Escape|keydown|onKeyDown` 此前 **0 命中**：三个 `role="dialog"` 弹窗只能点遮罩退出。现加一个 keydown 效果，Esc 按最上层依次关闭（评审 → 专家管理 → 知识库）。
**挂账**：focus trap / 焦点回位**未做** —— 键盘行为回归难归因，不与文案批混做（`minimal` 席同此建议）。

## 9. 注释与口径订正

- `src/silence.ts` 头部原写"本场现场复发 3 个席次"，与机器口径不符：本轮实测**至少复发 3 次**（`minimal` R1、`user` R2、`impl` R1–R2），但**补录按原轮次入账**，于是机器读到 `emptyRounds=0 / silentSeats=0 / lateReplies=1`。已在注释里写明**本判据对"补录"是盲的**：它只测"此刻账本是否完整"，不测"过程中是否曾经缺账"。
- 主持人自己的两处口径错误也记在此：导出头部**没有**"时长"字段（7 个字段实列）；导出的字节/行数是**时点值**（同一份导出三次测量 138,062 → 163,332 → 183,375 字节，会议在长），引用必须带测量时点。

**`impl` 席 R4 零产出留下 4 个验证问题，由主持人自查闭环（2/4）**：
1. **`ctx.get` 缺服务时的行为 —— 契约级证据，非推断**：cordis 自己的类型声明写明 `get(name: string, strict?: boolean): any`，文档注释为「@returns the service value, or **`undefined` when not (yet) provided**」；会抛错的是 `strict` 那一档。本插件用的是非 strict 读法，`projections_available: false` 分支因此是**契约允许**的路径，不是 try/catch 掩盖。
2. **按需端点耗时（"能不能被连点"）—— 热态实测**：真实会议（六席无活会话）48/8/6 ms；**5.09 MB 会话的活节点 4/4/5 ms**（`snapshot` 只需读已物化的投影单元）。结论：连点不会造成可观测冲击；另已加 `disabled={usageLoading}` 从源头挡住重入。**口径限定：冷态（宿主重启后首次折叠整条日志）未测**，不作为结论。
3. 其余两条（路由大 payload 回归、`sessionProjections` 在无 live 句柄时的降级路径）本轮未做 —— 前者由 `send()` 的先序列化加固 + 兜底 try 覆盖，后者即上面第 2 条的"休眠席位"挂账项。
