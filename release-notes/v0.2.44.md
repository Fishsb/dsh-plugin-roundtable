# RoundTable v0.2.44

**R-D 收尾批次：把"模式相关的口径"逐条实证并对账**。上一版把调度面板画进了 UI；本版按目标①逐项清理，又抓出**三条真遗留**——都是"同一件事两个判据/两条真相"这一类，正是最该先修的那一档。

## 1. 圆桌制对账假阳性（探针实测，非推理）

对账的"实际派发"集合原先**只认主持人**发出的定向消息。但 egalitarian 的设计就是**专家互相直达**（charter 第二节：“本职以外的请求直接转给名册里承担该职责的成员”）。于是：

```
探针实测（probe-egalitarian）：
[orchestrated] undispatched_owners=["impl"]
[egalitarian]  undispatched_owners=["impl"]   ← 但 impl 是被同伴 arch 唤醒的
```

`arch→impl` 这条**合法派单路径**被整条忽略，`impl` 被报成漏派；更荒谬的是 `arch` 作为发起者，只要计划里有它的项，也会一起被报成漏派。

**修法**：派发者随模式分叉 —— 单线制仍只认主持人（专家发给主持人的是**汇报**，不是派单），圆桌制下**节点→席位的直达计入派发**，且发起者不自计（A→B 只说明 B 被唤醒）。两种收件人恒不算派发：`captain` / `aggregator`。

**运行态实测**（真 egalitarian 会议，2 个真预设席位，验完即删）：让 `impl` 实际直发 `arch`，快照返回 `undispatchedOwners` **为空**（修复前为 `["impl"]`）。

## 2. `planned_owners` 算出来却没人看

`buildRoundSignals` 输出的席位侧分母只在"**有偏差时**"才被渲染 —— 读的人看不到比较基准，无法自行核对"这轮到底该派给谁"。字段进了 JSON、模型看不见，等于闸没接。

**修法**：`planned owners (seat level)` 改为**只要有计划就渲染**。

**并加守卫**：`R-D-UI ⑧` 用运行时 `Object.keys(buildRoundSignals(...))` 取全部字段，凡在 `tools.ts`/`snapshot.ts` 里找不到消费者即红 —— 以后再"加字段忘接线"会当场被拦住，而不是等人工发现。

## 3. 总纲与实现"两条真相"（圆桌制的 `[越界转派]`）

`dispatch.ts` 对圆桌制**不收集** `[越界转派]`（该标记是单线制的上行协议），但总纲的圆桌制段**只说了"直接转给同伴"，没说"不使用该标记"**。专家照着旧习惯写该标记，主持人机器上永远收不到 = 静默丢失。

**修法**：圆桌制段补一句显式声明（不使用的标记要说出来，否则"没实现"与"没收集"无法区分）。

**连带精确化一条旧守卫**：`persona.test.mjs` 的 A3 原断言是"圆桌制 persona **完全不含** `[越界转派]`"，与"必须声明不使用它"直接冲突。按"不得为使测试变绿而弱化断言"的口径，改为**按语境分**：
- 不得出现在"请用/该用"语境（`/请(在|用|按).{0,20}\[越界转派\]/` 不得匹配）；
- 不得出现单线制口径的"由主持人再分配"；
- **必须**出现"不使用 `[越界转派]`"的声明。

这不是放宽：把"教用"与"声明不用"分开，前者仍被禁，后者成了新要求（删掉声明句会让**两条**守卫同时变红，已实测）。

## 4. 硬门与模式的关系（显式化，非改动）

用户拍板的口径是"≥2 席必交计划"，**未按模式分叉**，圆桌制同样适用。这不是漏洞：推进轮次 = 花钱，任何模式下都该说清"本轮要让谁做什么、谁等谁"；圆桌制下专家的自组织只是**执行路径更多**，不改变"本轮意图"这件事。已把该口径写成文档 + 断言（`requiresDispatchPlan.length === 2`，结构上就分不了叉），免得日后被当成意外行为改掉。
