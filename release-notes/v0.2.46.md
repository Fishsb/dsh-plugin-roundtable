# RoundTable v0.2.46

**圆桌讨论模式**：两个入口、同一个状态。①在 Web UI 里打开「圆桌会议」Tab —— 打开即进入讨论模式；②敲 `/roundtable` 斜杠命令 —— 敲即进入。模式开着时，本会话之后发的**每条消息**都按圆桌会议处理，而不是单模型直接作答。

（v0.2.45 的「模型 · 思考强度」见 [v0.2.45.md](./v0.2.45.md)。）

---

## 1. 状态设计：一个有效值，两个来源标记

整套东西的要害只有一句：**`active = auto ∨ manual`，两个来源互不覆盖**。

| 来源 | 谁写 | 何时写 |
| --- | --- | --- |
| `auto` | 浏览器（`RoundTableView` 的挂载/卸载 effect） | 打开该 Tab = 开；切走 / 关页 = 关 |
| `manual` | `/roundtable` 命令（host `ctx.commands` 注册） | 敲命令开 / 关 |

为什么必须分开：把两个入口写成同一个布尔，最先坏掉的是"打开过 Tab 就再也关不掉模式"——Tab 挂在会话上，切走时若把共用布尔清零，用户在另一个 Tab 里敲的 `/roundtable` 就被悄悄撤掉了；反过来，命令开的模式若让 Tab 无法撤自己那一份，用户切走 Tab 后仍被强制进会议。

唯一例外是 `/roundtable off`：它 **两份一起撤**。命令的语义是"退模式"，若只清 `manual`，用户在 Tab 开着时敲 `off` 会看到**没有任何变化**（`auto` 仍为真）——那是假反馈，比不做还糟。

## 2. 模式的全部作用机制：一段条件化的 system prompt

新增 `roundtable:mode` 段（`order = roundtable:usage + 1`），**按会话求值**：`assemble.agent.session.id` 查到该会话处于模式中，就注入"本条消息按圆桌会议处理"；否则返回空串。

- **工具目录不变**：模式切换只改提示词，不动请求里的工具形状 —— 与宿主 plan-mode 同一取舍（请求缓存稳定）。
- **不重复 usage 协议**：`roundtable:usage`（16 条协议）本来就常驻，"怎么开会"不该写第二遍；模式段只讲"这条消息现在就按会议处理"。
- **拿不到 agent 就退化成空**（诊断装配、无会话场景），不抛错。

## 3. 命令语法

```text
/roundtable                       # 开启
/roundtable 评审 v0.5 的架构方案    # 开启 + 立刻把议题交给主持人
/roundtable off                   # 关闭（关 / disable / disable 同义）
```

裸调用即"开"是刻意的：用户的诉求就是"用斜杠命令就是开启圆桌会议讨论模式"，不该逼他再敲一个子命令。尾部非空文本一律当**议题**处理（开模式 + `agent.steer` 转交主持人，一次性启动会议）——`on`/`enable` 显式归入"开"。

## 4. UI：徽章显示 host 真值，不是本地猜测

Tab 头部新增模式徽章（`讨论模式 · 开 / 关`，命令开启时另标 `（命令开启）`）。

- 数据源是 **RPC 回包**（`mode.get` 轮询 5s，仅页面可见时），不是"我这次写成功了"的自证 —— 用户在别处敲 `/roundtable off` 也会正确反映。
- 真值未到之前**不画徽章**（`modeState === null`）：宁可晚一拍，也不要闪一个假状态。
- 卸载 cleanup 用 `alive` 标志丢弃晚到的回包：否则卸载后 `setState` 会给 React 报警，且徽章会显示已不再成立的状态。

## 5. 边界（明标，不把机制当现状）

**状态是进程内内存，不落盘。** DSH 重启或插件热重载后清零。自愈路径：重新打开「圆桌会议」Tab，或再敲一次 `/roundtable`。选择不落盘的理由：这是"此刻的交互意图"，不是配置；写成持久配置会让用户下次开会时莫名处于会议模式，而他自己想不起来何时开的。

## 6. 顺带修的坑：裸 `npm install` 把 peer junction 换成了实体副本

为拿到 `ctx.commands` 的类型，一度在本目录跑了 `npm install @deepseek-ai/dsh-commands`。它按 `package.json` 重算了依赖树，把 **36 个 `@deepseek-ai/*` 目录全部换成实体副本**（rc.2），而宿主装的是 **rc.1** —— 正是维护文档明令避免的"与宿主版本脱钩"。同时留下 `node_modules/.package-lock.json` 与 `package-lock.json` 漂移。

修复：36 个目录按维护纪律那套 `mklink /J` 重建回 junction；删 `node_modules/.package-lock.json`；`git checkout -- package-lock.json`。**结论：本仓加 devDependency 只手改 `package.json`（peer / peerMeta / devDeps 三处），绝不再跑裸 `npm install`。** 该结论已写进 `LOCAL-MAINTENANCE.md` §四。

## 9. 反验收（变异实测，九组）

把实现逐个改坏，确认对应守卫**真的转红**（"断言写了"与"断言有效"的分别）：

| # | 变异 | 结果 |
| --- | --- | --- |
| M1 | `isModeActive` 只看 `manual`（等于吃掉 tab 来源） | `# fail 1` ✓ |
| M2 | `off` 不撤 `auto`（假反馈防线失效） | `# fail 1` ✓ |
| M3 | 写 `auto` 时把 `manual` 一起顶掉（两来源互相覆盖） | `# fail 1` ✓ |
| M4 | 值未变也返回新对象（重渲染防护失效） | `# fail 1` ✓ |
| W1 | 命令面不再懒注入（`['commands']` → `['settings']`） | 首轮 **fail=0（假绿）** → 修强后 fail 1 ✓ |
| W2 | 模式段无条件返回文本（等于模式常开） | `# fail 1` ✓ |
| W3 | 卸载写 `active:false` → `true`（切走不撤模式） | 首轮 **fail=0（假绿）** → 修强后 fail 1 ✓ |
| W4 | 真值未到就画徽章（闪假状态） | `# fail 1` ✓ |
| W5 | `mode.set` 不校验 `active`（垃圾值写入） | `# fail 1` ✓ |

**W1 假绿的根因**：`assert.match(src, /ctx\.inject\(\['commands'\]/)` —— 同一句字符串**在注释里也写了**
（那段注释正是在解释"为什么用懒注入"），因此改坏真代码后断言照样通过。修法：新增 `stripLineComments`，
所有"锚点可能同时出现在注释里"的断言都在**去注释文本**上跑。

**W3 假绿的根因**：旧断言只查"文件里出现过 `active:false`"——挂载路径本来就写了一次 `active:true`…
准确说是 `write(true)` 与 cleanup 两个调用点，只查字符串存在性会被任一次冒充。修法：切出 **cleanup 切片**
（从 `return () => {` 起）后只在该切片内断言，并加"先立 `alive=false` 再发请求"的顺序断言。

**顺带踩到的工具坑（值得单独记）**：变异脚本第一版用 PowerShell `Set-Content` 回写源文件，
把 `src/index.ts` 的 UTF-8 中文写成了 ANSI（33138 → 33016 字节，read 工具直接报 `invalid UTF-8`）。
修法：变异只走 editor 工具（不碰编码），或回写时显式 `-Encoding utf8`。本轮从 `.mutbak` 全量恢复并复核。
