# v0.2.55：投递主持人的出处收进类型 —— 「同一语义两个入口两种真相」修复

**一句话**：仓内有 **5 处**向主持人投递消息的路径，封皮（"这句话是谁说的"）原本靠**每个调用点自己记得加**。实测**两处漏加**，而漏加的恰好是同一语义的两个入口。本版把封皮收进 `steerCaptain` 的**类型**（不给处出就编译不过），并顺带挖出并修掉一条**让 4 组反验收探针静默失效**的长期病灶。

## 1. 缘起：会话 `session-ef265a8a` 的 "/roundtable 没生效" 排查

用户报" `/roundtable` 为什么没生效"。实测结论：**机制是好的**（命令注册 → `command/run` → 模式段进提示词 → 议题转交 → 建会派单，全链路可证），真正的现象是**主持人自己延迟了 10 分 42 秒才开会**（先去跑 519 秒门禁基线）。此事不在本版范围。

但排查过程中，对全部 176 份会话日志做取证时发现一条**真缺陷**：

| 路径 | 封皮首行 |
|---|---|
| `/roundtable <议题>` 命令（`src/index.ts`） | **无**（裸传议题原文） |
| 空状态输入框（`src/rpc.ts` 的 `roundtable/steer`） | **无**（裸传） |
| 会议群聊 `roundtable/say` | `Message from the user (meeting group chat):` |
| 专家发言（`src/tools.ts` ×2） | `RoundTable message from <speaker>:` |

实测日志原文：命令路径转交出去的正文首字符就是 `整理一下我需要对整个项目做一次全量检查…`，**首行没有任何出处**。主持人因此读不出"这是用户给的议题"还是"插件自己注入的文本"——而 `rpc.ts` 自己注明两个入口"语义完全一致"。

## 2. 修法：把封皮从「5 个调用点的记忆」收进「类型」

`src/members.ts`：

```ts
export type CaptainProvenance =
  | { readonly kind: 'user-topic' }          // 命令 / 空状态输入框（共用）
  | { readonly kind: 'meeting-group-chat' }  // 群聊发言
  | { readonly kind: 'node'; readonly speaker: string }  // 专家发言

export function steerCaptain(captain, provenance: CaptainProvenance, body: string): boolean
```

- **为什么选类型级而不是运行时正则门**：零运行时代价、无新增失败路径；且 `npm run typecheck` 本就在构建链里。
- **为什么封皮只有一个产地**：新增 `provenanceLabel()` 是唯一渲染点 —— 掏空它会被守卫抓（变异 31 实证）。
- 5 个调用点全部改造；`src/index.ts` 的 `createUserMessage` 直接导入随之删除。

## 3. 顺带挖出的长期病灶：4 组反验收探针**从来没在测东西**

`test/mutate.mjs` 是"断言写了 ≠ 断言有效"的反验收工具。实测发现其中 **2 / 14 / 19 / 20 四条**（全在 `rpc.ts`）每次都走到「锚点没找到」分支 `exit 3` 退出。

**根因**：本机 `core.autocrlf=true` 且仓内**无 `.gitattributes`** ⇒ 工作区 `src/rpc.ts` 是 **CRLF**，而多行锚点字面量里的 `\n` 是 **LF** ⇒ `original.includes(from)` 恒 false。

**为什么长期没人发现**：`npm test` 只跑 `test/*.test.mjs`，**从不执行 `mutate.mjs`** ⇒ 那四条死掉时，全仓 352 条测试**全绿**。这正是用户反复点名的「让失败不可观测」类缺陷：工具在，但它不说话。

**两手修**：
1. `mutate.mjs` 比较与替换两处做**行尾归一**（锚点保持可读的 LF 写法，与工作区解耦；LF 检出环境同样成立）。修后实测 **31/31 全部转红**（原 27/31）。
2. 新增 `test/mutation-probe-health.test.mjs`（4 条）把这类失效**变成常驻信号**：解析探针表 + 逐条断言锚点在当前工作区文件里找得到 + 编号连续唯一 + **反例自证**（未归一的 CRLF 源必须解析不出来）。

> ⚠ 本门首版自己就栽在同一个坑：解析 `mutate.mjs` 时用了 LF-only 正则 ⇒ 解析到 **0 条** ⇒ 后两条断言在**空列表**上"通过"（又一个假绿）。故 test 1 的非空断言是其余各条的前提，且下面每条自带非空检查。

## 5.5 根因修复：`.gitattributes` 把行尾从「偶然」变「契约」

§3 的行尾归一是在**消费方**（`mutate.mjs`）做的兜底 —— 它让探针在任何行尾下都能工作，
但**没有消除**"工作区行尾取决于本机 git 配置"这一根因。授权后补做根因修复。

**先取证再动手**（148 个受控文件全量清点）：
- 工作区：**13 个 CRLF / 111 个 LF**（CRLF 集中在 `src/*.ts`、`package.json` 等，即 autocrlf 挑中的那些）
- **git 索引里：13/13 全为 LF**；`git check-attr text/eol` 全为 `unspecified`
- ⇒ 加 `* text=auto eol=lf` **不产生任何索引变更**，只是把既有事实写明确

**决定性判据**：跑 `git add --renormalize .` 前后逐条比对索引 blob 哈希 ⇒
**148→148，非有意副作用 0**（9 处变化全是我本次有意改动的文件）。

**边界（写进文件头，避免被后人通配规则覆盖）**：
- `scripts/process-logos.ps1` 是唯一行尾敏感件（本仓当前为 LF 且实测可用）→ 显式声明 `text eol=lf` 固定现状；将来若加 `.bat`/`.cmd`（cmd.exe 对 LF 处理不良）须单独声明 `crlf`，**不得用 `*` 兜**。
- 二进制件 19 个（含 NUL 的 `.txt` 日志 12 · `.png` 5 · `.jpg` 2）→ 显式 `binary`，禁止行尾转换（否则 git 改写字节、产物损坏）。
- 反例防护：禁止用 `* text=auto`（**无 eol**）兜底 —— 那等于没固定行尾。已入守卫。
