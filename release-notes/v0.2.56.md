# v0.2.56：边界的可判定性 —— 吸收 P10「成功标准须可量化」

**一句话**：一条边界可以"填了却验不了"——`boundary_done` 写了「算解决的标准」，但没人写下**拿什么检查**，于是"完成"退化成一句无法验证的主张。本版把 P10 CTO 战略输入模板里的 *成功标准须可量化* 落成 `boundary.check` 字段，并把"有 done 无 check"变成每轮可见的信号。

## 1. 缘起：检索外部协议，只在这一点上有真增量

用户要求评估外部「P10 CTO / 架构委员会协议」（`tanweai/pua`）对本项目是否有帮助。实测结论分三层：

| 层次 | P10 协议 | 本项目 | 判定 |
|---|---|---|---|
| 治理门禁 | 散文规约（"不写 Task Prompt"、P9 间冲突要拍板），靠模型自觉 | `src/dispatch.ts` **代码级拒收**：change 无 review 依赖即拒；同席/交叉自审即拒；`depends_on` 波次；`regression_risk` 计数 | **本项目更硬，无增量** |
| 战略输入完整性 | 模板要求「成功标准**可量化**」 | boundary 三字段只检查**存在性**，不看有没有检查方式 | ⚠ **唯一真缺口** |
| 话术施压层 | L0–L4 绩效施压 + 14 种大厂风格 | —— | **不采纳**：情绪施压不是判据，撞 `[原则] 代理指标非判据`；其 benchmark 为作者自报，且仓库自称 MIT 但根 `LICENSE` 404（GitHub API `license: null`） |

**结构性冲突（记录以免后人照搬）**：P10 模板要求写明「P9 间接口」，即让同级席位互相知道边界；本项目 single-line 模式**刻意**不让专家知道彼此（`charter.ts` 单线制省略 roster/edges）。P10 的组织模型在这里是反模式，只可采用其**战略输入字段**，不可采用其**组织拓扑**。

## 2. 修法：新增第四个边界字段 `check`，采**结构性**判据

```
boundary_check: 怎么检查才算达标（命令 / 字节比对 / 审计态）
```

贯通五段链：类型（`types.ts`） → 设置卡（`plan.ts`） → 总纲（`charter.ts`，每个专家的 persona） → `status`（消费面，含缺口信号） → 导出物（`tools.ts`）。

**⚠ 为什么是"新增字段"而不是"给 done 做模糊词判定"——一次主动放弃**：

初版方案是"`done` 里出现「性能良好 / 体验流畅」这类词就标红"。**主动放弃**，因为那正是本项目 `test/double-truth-guards.test.mjs` ⑦-c 已明令禁止的**分类启发式**（"只呈现不判定"）——关键词表会造出假红假绿，是本插件反复在剿的形态。

改采**结构性**判据：不问"写得够不够量化"（机器判不了），只问"**有没有写下检查方式**"（存在性，确定性可判）。措辞由用户与专家评判，机器只保证这件事**不出声就不会被忽略**。

缺口信号（`status` 每轮渲染）：

```
        check: (unset — no way to check, so "done" cannot be verified)
    ⚠ a done-standard is declared but NOT how to check it — write the check
      (command / byte compare / audit state), otherwise "done" is a claim nobody can verify.
```

## 3. 判据与实测

| 判据 | 结果 |
|---|---|
| 全仓测试 | **364 pass / 0 fail**（361 → 365，新增 4 条功能测试） |
| 功能探针（真调渲染函数） | `buildCharter` / `formatMeetingDraft` / `renderMeetingMarkdown` 三处均含 check 正文 |
| **先红证伪** | 同一组断言在**原始源码**上：总纲/导出 **1/6**、卡片 **1/4** 通过（唯一恒真项是改动前既存的"不许动"行）⇒ 断言非平凡 |
| 缺 check 时 | 三处均显式出声（`（未声明）` / "多半不可判定"），不留白成假完整 |
| 既有边界面 | "不许动那面墙"行在三处均未丢（防拆东墙的判据本身没被拆） |
| 新增变异探针 | 32（导出物丢 check）/ 33（总纲丢 check） |
| 版本三处一致 | `package.json` / `src/version.ts` 同批 |

## 4. 新增守卫

- `test/boundary-check-render.test.mjs`（4 条）：**功能测试**——真调用渲染函数验证值抵达输出。与 `double-truth-guards` ⑩ 的**文本断言**互补：文本断言能抓"文案说 A、实现做 B"，抓不到"接线在、渲染出来却是空"。
- `test/double-truth-guards.test.mjs` ⑩-a/⑩-b/⑩-c：五段贯通 / 缺口必须出声 / **不得内置模糊词表**（把"主动放弃启发式"这一决定钉成常驻判据，防后人加回）。
- `test/build-artifact-guards.test.mjs`：产物须含 `怎么检查才算达标` 标记。

## 5. 边界（未做）

- **未**改 `boundary_done` / `boundary_not_doing` 的语义，**未**引入任何关键词判定。
- **未**把 `check` 设成必填 —— 强制会逼出凑数文字（与 ⑥ 的判断一致：显式警示 + 用户核对才是闸）。
- **未**新增角色预设覆盖 P10 职能：现有 `arch`（架构主审）+ `converge`（收敛裁决）已覆盖架构委员会主席的实质工作，加一条预设属冗余（且预设是用户资产，项目不得点名）。
- 未采用 P10 的 P9 编制 / 席位互联模型（与单线制隔离结构性冲突，见 §1）。

## 6. 判因留档（一次自我纠错）

我上一轮给用户的建议原文是"把 `boundary_done` 不可判定时**标红**"。动手前读项目自己的守卫才发现：**该建议直接违反本仓 ⑦-c**（禁止分类启发式）。已就地改为结构性判据，并把这次纠错钉成 ⑩-c 常驻断言——避免我或后人再提同样的方案。
