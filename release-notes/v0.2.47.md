# RoundTable v0.2.47

**圆桌会议 Tab 内嵌「群聊」窗口**：会议里主持人/专家的发言，用 QQ 群聊的形态展示在一个**可切换的第二视图**里；底部输入框能让用户以主持人身份直接往会议里说一句话。拓扑视图、右栏面板、全部既有行为**一个都没动**。

（v0.2.46 的圆桌讨论模式见 [v0.2.46.md](./v0.2.46.md)。）

---

## 1. 一个 Tab，两个视图

Tab 的 `main` 区顶部多了一条切换条（`拓扑 | 群聊`），默认仍是拓扑 —— 打开 Tab 看到的东西和以前**完全一样**。

- 切换状态存在组件内 `useState`，**刻意不落盘**。理由与「讨论模式不落盘」同一条：这是"此刻在看什么"的交互意图，不是配置。写成持久配置的结果是用户下次打开 Tab 时莫名不在预期的视图上，而他自己想不起来何时切的。
- 群聊视图下，拓扑画布与 digest 摘要区**不渲染**（二者都是拓扑语言）；右栏 7 个面板在两个视图下完全一致，切换不隐藏、不重载。

### 抗堆叠：同一份信息不并列两份

digest 里原有一条「发言时间轴」（批次 B ③ 的产物，其唯一独占信息是时间戳）。群聊窗口本身就是这批发言的完整呈现，两处并列就是同一份信息的两份拷贝 —— 所以**时间轴改为仅在拓扑视图渲染**。

没有直接删掉它：群聊气泡虽然自带时间，但拓扑视图下那条时间轴仍是该视图里唯一能看到"什么时候说了什么"的地方。加一个视图条件即可两全。

## 2. 数据源：按需拉取，绝不污染 1Hz 轮询

群聊要显示**完整发言**，而快照里的 `recent` 只有 20 条、正文被 `compactText(..., 90)` 截到 90 字。两条路可选，选了后者：

| 方案 | 后果 |
| --- | --- |
| 放宽 `recent` 的上限/截断 | 让**每场会议每一次轮询**都变大（实测 16 会议 301 KB / 44.5 ms），而群聊只在其窗口打开时才需要全量 |
| **新增按需端点 `roundtable/transcript.list`** | 轮询体保持原字节；只在打开群聊时拉一次全量，之后按 `since` 增量补齐 |

- 端点入参 `{ meetingId, since?, limit? }`，`limit` 由 `clampTranscriptLimit` 夹取到 `[1, 1000]`（默认 200）。**不设无界读**。
- `since` 是**严格大于**：增量窗口不会把边界那条重复送回，前端也就不必再靠 ts 兜底去重。
- 超限时取**尾部**（群聊看最新），但按升序返回 —— 气泡顺序即时间顺序，前端不重排。

### 权限边界（写给后人）

`roundtable/transcript.list` 服务于**浏览器的用户视角**：用户是会议的信息枢纽，理应看到全部发言。它与专家侧 `roundtable_status` 的 `statusVisibility` 过滤（`visibility.ts`）是**两套独立权限** —— 禁止拿 `statusVisibility` 来过滤这个端点，那会让用户在群聊里看不到自己会议的全貌。这条已钉进端点实现旁的注释，并有测试守卫。

## 3. 发言通道：`roundtable/say`

用户在群聊里说的话，落成一条主持人发言：

```
nodeKey: 'captain'   kind: 'speech'   source: 'user'   to: (空 = 交给汇聚网关)
```

**为什么必须加 `source: 'user'`**：`nodeKey` 只有 `captain` 一个身份位（用户就是主持人本人）。不加这个标记，主持人下一轮读 transcript 时**无法区分「用户亲口说的」与「我自己说的」**，会把用户的话当成自己的话。那是归因错误，不是风格问题。

写入走 `appendUtterance`（自带 per-meeting 锁），与主持人工具 `roundtable_speak` 同一条落盘路径 —— 不自己拼文件、不绕过 state 层。

### 不做乐观插入

发送后**以 host 回包为准回读一次增量**，而不是先把这条塞进列表。失败时群聊里不会留下一条"显示了但没落盘"的假消息。

## 4. 群聊窗口的形态

- **群头**：群公告位放会议目标，副行是成员数（`1 + 存活专家数`）。刻意不重复会议名 —— Tab 头部 titleRow 是唯一来源。
- **成员表**：`captain` + 未移除的专家。**`aggregator` 不画成人**：它在 `MeetingUtterance` 里只出现在 `to`，不是发言者。
- **头像**：复用拓扑视图已有的 `providerBrand`（9 个 provider 的品牌 logo 随包构建），不新增图片资源。
- **气泡**：QQ 形态的不对称圆角（表达说话方向）、连续同人合并（3 分钟窗口内不重复画头像昵称）、日期分隔线 + 轮次分隔线。
- **发言去向**：气泡下方标 `→ 汇聚网关` 或 `→ 某席`。QQ 没有这个，但会议里"发给谁"是真实信息 —— 不显示会让单线制/圆桌制的差别在群聊里彻底不可见。
- **滚动**：仅当用户已在底部附近（48px 内）时自动跟随最新；正在上翻历史时**绝不**把他顶走。

## 5. 工程边界

- `ChatView.tsx` + `ChatView.module.css` 是**新文件**，不并入 1950 行的 `RoundTableView.tsx`、也不复用它的 216 个样式类 —— 两者没有共享的可变状态，混在一起只会让"改群聊碰到拓扑"成为可能。
- `ChatView` 是**纯展示组件**：自己不发 RPC，数据与动作全由父级传入。将来若要换成真实数据源（例如接 QQ 协议端），改父级取数即可，UI 不返工。
- 窗口切换后**重新测量画布**（测量 effect 依赖 `view`）：切到群聊时画布卸载，切回来的是**新** DOM 节点，若不在切回时重跑，`ResizeObserver` 会一直盯着那个已卸载的旧节点，新画布拿到 `size=0`，节点全挤在默认坐标上。

### 变异探针发现的假绿（已就地修强）

第一轮 `mutate.mjs` 有 4 条报 FAIL —— **不是实现坏了，是我的守卫写得不够硬**：

| # | 假绿写法 | 为什么恒真 | 修法 |
| --- | --- | --- | --- |
| 1 | `includes('out.length < 20')` | `'…< 200'.includes('…< 20')` 为真 | 改词边界正则 `/out\.length < 20\b(?!\d)/` |
| 7 | 断言文案含 `混合`，实现输出不含该词 | 判定条件写成了"输出含期望文案" | 判定只看 `# fail` 数（基线 0，变异后 >0 即抓到） |
| 9 | `slice(at, src.indexOf('}, [view])', at))` | 找不到时 `indexOf` 返回 -1，`slice(at, -1)` 给出一大段字符串，断言通过 | 先断言两个 `indexOf` 都命中 |
| 10 | 同 7 | 同 7 | 同 7 |

另有一处**探针自身的缺陷**：第一版 `mutate.mjs` 把 `Out-String` 输出误写到了源文件，导致 `snapshot.ts` 被反复覆写、且编码被改坏。已用 `git checkout -- src/snapshot.ts` 恢复并逐字节核对（与 HEAD 一致）。修正后的探针只在 `finally` 里写回**读到的原始内容**，且每次运行都从 `readFileSync` 取值，不留残留。
