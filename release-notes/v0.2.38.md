# RoundTable v0.2.38

**修 v0.2.37 单线制隔离的一个真漏洞：专家面通过连线读到同伴标识。**

---

## 1. 漏洞（v0.2.37 引入）

v0.2.37 的「单线制专家互不披露」在专家面用 `statusVisibility()` 的谓词过滤 `roundtable_status` 快照，但边谓词写成了**「自己参与的一切边」**：

```ts
edge: (edge) => edge.from === key || edge.to === key      // 旧
```

后果：单线制会议里若主持人连过 `a → b`，节点 `a` 调 `roundtable_status` 会在 `edges` 里读到 `a → b`，**由此知道同伴 `b` 的 key 存在**——隔离被绕过。这是公开信息面（prompt）说了 A、可查数据面（tool）做了 B 的典型假隔离。

## 2. 根因：测试漏了一格，所以全绿是假绿

`test/visibility.test.mjs` 的边断言覆盖了 `captain→a`(true)、`a→captain`(true)、`captain→b`(false)、`b→c`(false)，**恰好缺 `a→b` 这一格**——而它正是唯一会泄露同伴的格。114/114 全绿并不代表隔离成立。

> 发现者：圆桌会议「UI 优化会审 · RoundTable Web 端」的架构席（`arch` 第 2 轮），它读码后**推翻了主持人上一轮的裁决**（该裁决只看提示词侧，判「未发现」）。主持人复核三处（谓词、消费点 `tools.ts:1245-1250`、测试缺口）后确认成立。

## 3. 修法

```ts
// 只放行「自己 ↔ 主持人」与「自己 ↔ 汇聚网关」两类边
edge: (edge) => {
  if (edge.from !== key && edge.to !== key) return false
  const other = edge.from === key ? edge.to : edge.from
  return other === CAPTAIN_KEY || other === AGGREGATOR_KEY
}
```

网关不是同伴（本职通道），故保留；任何**同伴端点**一律不可见。

## 4. 证据（改前必失败 / 改后必通过）

| 步 | 命令 | 结果 |
| --- | --- | --- |
| 改前 | `node --test test/visibility.test.mjs` | **fail 1** —— `a→b 不得暴露同伴 b` |
| 改后 | 同上 | **7/7 通过** |
| 回归 | `node --test` | **114/114 通过** |
| 类型 | `npx tsc --noEmit -p tsconfig.json` | exit 0 |

新增断言：`a→b` = false、`b→a` = false、`a→aggregator` = true、`aggregator→a` = true。

## 5. 兼容性

- 仅收紧**单线制节点**的 `roundtable_status` 视图；主持人（全量）与 egalitarian（全量）不变。
- 不影响会议状态、连线本身、UI 拓扑（用户视角本就该看到全员与全部连线）。
- 已 spawn 的节点其工具面是 spawn 时定型的，**新建会议或重建节点后**生效。
